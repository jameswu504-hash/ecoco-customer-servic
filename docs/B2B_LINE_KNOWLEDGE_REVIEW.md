# B2B LINE 對話轉待審知識

## 目的

把已綁定 LINE 群組中自動保存的歷史訊息，整理成 AI 友善、可追溯且必須人工核准的公司知識。未核准資料不會進入 B2B RAG。

## 第一版操作

1. 進入 `/partners.html`，選擇合作公司。
2. 在「LINE 待審知識」按「整理今天」或「整理最近 7 天」。
3. 系統依公司、群組及台灣日期建立批次。
4. 固定內部規則會略過問候、附件占位及系統錯誤，並保留來源訊息 ID。
5. Bot 回覆只作為待審證據；人工核准前，問題仍標示為「尚待確認」，不會自動產生已確認事實。
6. PM／營運可修改標題、分類和 AI 友善內容。
7. 選擇核准、退回或封存。
8. 只有按下「核准並匯入 RAG」後，才建立 `partner_knowledge_sections` 與 `partner_knowledge_chunks`。

## 隱私與隔離

- TXT／MD 原始檔仍只在使用者瀏覽器清洗。
- 自動保存的 LINE 訊息原本就在 Render／PostgreSQL；這個流程只在 ECOCO 應用程式內用 JavaScript 固定規則整理。
- 整理過程不呼叫 Claude、OpenAI、Embedding API 或其他外部 AI。
- LINE 保存階段已遮蔽的電話、Email 與識別資料不會被還原。
- 查詢、批次、候選、核准與 RAG 寫入全部以 `company_id` 隔離。

## 去重與追溯

- 批次雜湊由該公司、群組、日期及來源訊息集合產生。
- 候選雜湊包含來源訊息 ID 與整理內容。
- 同一批對話重跑不會重複建立候選。
- 每個核准 Chunk 保存候選 ID、批次 ID、群組、日期及來源訊息 ID。

## 封存與刪除

- 封存某日 LINE 訊息時，同日尚未核准或已退回候選會一併封存。
- 永久刪除某日 LINE 訊息時，同日未核准候選會一併刪除。
- 對話與候選的封存／刪除使用同一個資料庫交易；任一步失敗都會整批回滾。
- 未封存的日期無法永久刪除，也不會誤刪同日候選。
- 已核准候選及其正式知識不會因原始 LINE 紀錄封存或刪除而自動消失。

## 第一版限制

- 第一版由管理者手動觸發，不會每收到一則 LINE 就自動整理。
- 使用固定規則，不做外部 LLM 摘要；品質由人工預覽與編輯補足。
- 每次整理最多使用最新 2,000 則訊息；超過時前台會顯示截斷提示。
- 未核准候選不會被 Bot 檢索。
