# B2B LINE 對話轉知識審核

## 原則

LINE 對話是工作紀錄，不是已確認事實。系統可以整理候選知識，但只有人工核准的內容才能進入公司專屬 RAG。

## 流程

1. 已綁定群組的對話寫入 `partner_conversations`。
2. 管理者依公司、群組與日期選取一批對話。
3. 系統以固定規則整理主題、事實、決策、待辦、來源訊息與日期。
4. 結果寫入 `partner_knowledge_candidates`，初始狀態為 `pending_review`。
5. 管理者修改、核准或拒絕候選內容。
6. 核准後建立同一 `company_id` 的 `partner_knowledge_sections` 與 `partner_knowledge_chunks`。
7. 後續 B2B 問答才能檢索這些 chunks。

## 修訂已核准知識

已核准候選會鎖定，不能直接覆寫。需要更新時：

1. 在已核准候選按「建立修訂版本」。
2. 系統複製內容為新的 `pending_review` 候選，並保存前一版候選 ID 與版本序號。
3. 管理者編輯新版內容；此時正式 RAG 仍使用舊版。
4. 新版核准後建立新的 Section 與 chunks，再封存被取代的舊 Section。
5. 舊候選與來源訊息保留，供追溯修改前後差異。

## 狀態

| 狀態 | 意義 |
|---|---|
| `pending_review` | 等待人工確認，不可供 Bot 回答 |
| `approved` | 已核准並建立公司知識 |
| `rejected` | 不採用，保留審核紀錄 |
| `archived` | 暫時不顯示或不使用，但保留資料 |

已核准候選不可重複建立相同知識；完全相同的重送應回傳原結果。若內容需要修改，必須建立修訂版本，避免悄悄改寫已核准的來源紀錄。

## 審核要點

- 只保留可驗證的合作規則、決策、窗口、處理方式與有效待辦。
- 閒聊、猜測、過期狀態與未確認說法不得核准。
- 標記適用公司、主題、有效期間與來源日期。
- 姓名、電話、Email 僅在 B2B 作業確有需要時保留。
- 涉及其他公司時拆開處理，不得放進目前公司的知識。

## 封存與刪除

- 測試或暫時不用的內容優先封存，日後可恢復。
- 確認無保存價值且不需稽核時才刪除。
- 刪除正式知識時必須同步移除或停用對應 chunks，避免仍被 RAG 搜到。
