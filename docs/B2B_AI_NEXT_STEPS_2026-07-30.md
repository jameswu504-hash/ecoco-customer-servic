# B2B AI 後續兩階段構想

日期：2026-07-30

## 現在已完成的基礎

- LINE 綁定群組的訊息會依公司與台灣日期保存。
- 公司知識與 LINE 每日紀錄都能封存、恢復及永久刪除。
- 封存的知識不會進入 RAG。
- 封存的 LINE 紀錄不會進入 Bot 的歷史上下文。
- 永久刪除只允許已封存資料，並需要再次輸入公司代號或日期。
- 原始 LINE 對話與正式知識分開保存。

## 下一步：對話自動轉成「待審知識」

### 目標

讓 LINE 對話持續保存後，自動整理出可供人工審核的知識候選，但不能未經確認直接影響 Bot 回答。

### 建議流程

1. 以 `company_id + LINE 群組 + 台灣日期` 建立每日批次。
2. 排除已封存、已刪除、純問候、重複訊息與系統錯誤。
3. 使用公司 Local 端的固定清洗 Skill 整理，不把姓名、電話或 Email 傳給外部模型。
4. 產生以下候選結構：
   - 主題
   - 摘要
   - 已確認事實
   - 尚未確認事項
   - 待辦或決策
   - 來源日期與訊息 ID
   - 有效期限或時效風險
5. 候選狀態只能是：
   - `pending_review`
   - `approved`
   - `rejected`
   - `archived`
6. PM 或營運在後台預覽、修改並核准。
7. 核准後才寫入公司專屬知識與 RAG chunks。

### 資料表建議

- `partner_conversation_batches`
  - 保存批次日期、群組、公司、訊息範圍及清洗狀態。
- `partner_knowledge_candidates`
  - 保存待審摘要、事實、來源引用、風險與審核狀態。
- 延用既有：
  - `partner_source_documents`
  - `partner_cleaning_jobs`
  - `partner_knowledge_sections`
  - `partner_knowledge_chunks`

### 防呆規則

- 同一批訊息以 `content_hash` 去重，不重複建立候選。
- 候選必須保存來源訊息 ID，回答內容才能追溯。
- 報價、期限、排程、合約與尚未確認事項必須標記時效風險。
- 封存 LINE 日期時，尚未核准的候選也一併封存。
- 正式知識不因原始對話封存而自動刪除，避免已核准內容意外消失。

### 第一版觸發方式

- 後台按鈕：「整理最近一天／七天對話」。
- 驗證穩定後才增加每天固定排程。
- 第一版不建議每收到一則 LINE 就立即切片，避免產生大量破碎與重複知識。

### 驗收條件

- 未核准候選完全不會進入 RAG。
- 不同 `company_id` 永遠無法互相查到候選或知識。
- 已封存 LINE 訊息不會建立新候選。
- 核准後能看到來源、Skill 版本、建立時間與審核人。
- 重新執行同一日期不會重複產生候選。

## 下下步：公司專屬 Agent 記憶與任務

### 目標

讓 Agent 不只回答歷史資料，也能協助 PM 與營運回憶狀況、整理待辦及追蹤責任人。

### 必須分開的三種資料

1. **知識**
   - 已確認、可重複回答的公司資料。
2. **記憶**
   - 某群組目前的背景、決策脈絡與進行中狀態。
3. **任務**
   - 有負責人、期限、狀態與下一動作的工作項目。

三者不可混在同一張 RAG 表，否則過期任務容易被當成正式知識回答。

### Agent 第一批能力

- 「幫我回顧全家群組這週發生什麼事」
- 「有哪些事情還沒確認」
- 「列出待清查、設備檢查與派工事項」
- 「這個站點最近被討論過什麼」
- 「把這件事建立成待辦，指定 PM／營運」

### 權限與安全

- 每個 Agent 固定綁定 `company_id`。
- Skill 依角色開放：
  - PM：回顧、需求、時程、任務指派。
  - 營運：站點、設備、清運、派工狀態。
  - 品牌方：只讀該品牌知識與已核准進度。
- 任何外部派工、通知、行事曆或訊息發送，第一版都必須人工確認。
- 所有 Agent 動作寫入稽核紀錄。

### 建議資料表

- `partner_memories`
  - 公司、群組、主題、摘要、有效期間、來源與狀態。
- `partner_tasks`
  - 任務類型、負責角色、負責人、期限、狀態、來源訊息與外部系統 ID。
- `partner_agent_actions`
  - 建議動作、人工確認人、執行結果與錯誤。

### 建議實作順序

1. 只做群組回顧與未決事項，不執行外部動作。
2. 加入人工建立／更新待辦。
3. 串 ECOCO Hive 的唯讀站點與派工查詢。
4. 最後才允許經人工確認後建立派工、通知或行事曆。

## 暫時不要做

- 不要讓未審核 LINE 對話直接進正式 RAG。
- 不要把知識、記憶及任務混成同一種 chunk。
- Local／瀏覽器清洗階段不得把內部聯絡資料傳給外部 AI；B2B 回答階段只允許傳送該問題命中的必要 RAG 片段。
- 不要讓 Agent 未經確認直接派工、發訊息或修改營運資料。
