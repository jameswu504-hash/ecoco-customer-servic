## 3. IoT Architecture

The production path is:

```text
Local Windows machine / company network
  -> readonly Azure MySQL
  -> npm run iot:sync
  -> Render protected sync API
  -> PostgreSQL / Neon station_statuses
  -> Render bot reads PostgreSQL
```

Important:

- Render direct access to Azure MySQL previously timed out on port 3306 because of networking/firewall rules.
- The supported workaround is not a firewall bypass. The local Windows task reads MySQL from the reachable network and uploads the normalized snapshot to Render.
- The bot continues working if the local machine stops, but station data becomes stale.
- Render currently still reports `liveMysqlIotEnabled=true`, which means `ECOCO_IOT_MYSQL_*` variables remain configured there. The PostgreSQL-first path is working, but these Render variables can still produce useless timeout attempts in some diagnostic paths.
- After confirming the local sync remains healthy, consider removing the direct MySQL variables from Render. Keep the MySQL credentials only on the local/VPN side.

## 4. B2B LINE Architecture

The same LINE Official Account supports two isolated paths:

- One-to-one LINE messages: existing B2C customer service.
- LINE group messages: B2B gate.
- Bound B2B group: only ECOCO shared knowledge plus the bound company's private knowledge.
- Unbound group: binding instructions only; it does not fall through to B2C RAG.

Tenant isolation is enforced by backend `company_id` queries, not only by prompts. Cross-company questions are denied before model access.
